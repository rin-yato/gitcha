## Why this matters

Three dependency inefficiencies in `package.json`:

1. `dequal` (`^2.0.3`) is a declared dependency but never imported anywhere in `src/` or `scripts/`.
2. `isbinaryfile` (`^6.0.0`) is a declared dependency but never imported anywhere in `src/` or `scripts/`.
3. `remeda` (`^2.37.0`) is imported in exactly one place: `src/component/ui/select/index.tsx:15` for `isDeepEqual` only. Meanwhile `dequal` is dead but provides equivalent deep-equality.

This plan removes the dead deps and consolidates on one deep-equality library.

## Strategy

We keep `dequal` (lighter, ~1KB) and remove `remeda` (~20KB) and `isbinaryfile` (~50KB). The select component imports `isDeepEqual` from `remeda`; we replace it with `dequal` from `dequal`.

## Steps

### Step 1: Verify dequal and isBinaryFile behavior match

`dequal` does deep equality on plain objects, arrays, Dates, RegExps, Maps, and Sets. The select component compares filter state objects (`FilteredGroup`, `FilteredOption` types). These are plain objects — `dequal` handles them identically to `remeda`'s `isDeepEqual`.

### Step 2: Update select/index.tsx import

In `src/component/ui/select/index.tsx`, replace line 15:

```typescript
// Before:
import { isDeepEqual } from "remeda";

// After:
import { dequal as isDeepEqual } from "dequal";
```

The alias `as isDeepEqual` keeps the local variable name unchanged — no other code in this file needs to change.

**Verify**: `grep -rn "remeda" src/` returns no matches.

### Step 3: Update package.json

Remove `dequal`, `isbinaryfile`, and `remeda` from `dependencies`. Add `dequal` back (it was already there, so keep it — just remove `remeda` and `isbinaryfile`).

After the edit, the `dependencies` in `package.json` should NOT include `isbinaryfile` or `remeda`. `dequal` stays.

### Step 4: Install and verify

Run `bun install` to regenerate `bun.lock`.

**Verify**: `bun run typecheck` → exit 0
**Verify**: `bun test src` → all pass
**Verify**: `bun run fix` → exit 0
